# Mapping decisions and review policy

This document accompanies `refactor/mapping-rules.json`. The JSON is the machine-readable
policy; this file explains judgments that later agents and human reviewers must preserve.

## D01 — The two classifications are related, not equivalent

UNI 8290 classifies the functional role of technological units and technical elements. IFC
models occurrences, systems, assemblies, processes, and resources. A mapping therefore states
that an IFC occurrence may honestly receive a UNI code in a stated context; it does not assert
that the two taxonomies have identical scope.

## D02 — Exhaustive screening is not exhaustive assignment

Every one of the 876 IFC 4.3.2 entities must receive a screening outcome. Only concrete,
semantically applicable occurrences may be selected. An eligible IFC entity can correctly end
with `SCR_NOT_APPLICABLE`; a UNI class may correctly have no IFC mapping if IFC has no reliable
direct equivalent.

## D03 — Hierarchy is mandatory semantic input

Generic leaves such as `Alimentazione`, `Macchine`, `Rete`, `Terminali`, and `Allacciamenti`
must be read through their full parent path. A heating network and an electrical network are not
mapped by taking the union of every entity that can occur in any distribution system.

## D04 — Parent decisions are independent

A parent class represents its own aggregate function. Its mapping is not generated by unioning
all selected child entities. Likewise, a child need not be an IFC subtype of its parent's entity
when IFC and UNI organize the concepts on different axes.

## D05 — Conditions are first-class evidence

`RelatedIfcEntityNamesList` contains entity names only. When a mapping is valid only for a
PredefinedType, system membership, load-bearing role, exterior/interior role, or another property,
the decision matrix must state that condition. Reviewers must not read an unrecorded condition
into a broad mapping.

## D06 — Components are not inherited into every assembly

Fasteners, plates, reinforcement, signals, signs, bearings, coverings, and similar elements are
selected only when the UNI class directly classifies that element. Their possible presence in a
wall, system, enclosure, or item of equipment is not sufficient.

## D07 — Review thresholds are warnings

The cardinality thresholds in `mapping-rules.json` identify decisions that need additional
attention; they are not hard numerical limits. A combined service-network class can legitimately
need several media-specific entities if every entity is directly applicable and individually
justified.

## D08 — Human branch review remains required

Automated schema checks can prove existence and technical eligibility, but cannot approve the
semantic classification. P05 must explicitly approve or flag each of the eight UNI branches.
Medium-confidence and domain-review-required decisions must remain visible and must not be treated
as approved merely because generated tests pass.

## D09 — Source and authored content remain distinguishable

Official UNI names, existing definitions, newly authored non-normative definitions, and English
translations must retain provenance. Technical completion does not resolve rights to reproduce,
translate, name, license, or redistribute UNI content.
